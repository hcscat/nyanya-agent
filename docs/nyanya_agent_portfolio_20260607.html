1. 프로젝트 소개

NyaNya Agent는 개인 또는 소규모 팀의 로컬 작업 환경을 Discord/Telegram과 연결해, 메신저에서 들어온 요청을 로컬 LLM 백엔드 또는 Codex CLI 작업으로 안전하게 라우팅하고 처리 이력을 로컬 대시보드에서 추적하는 경량 Python 에이전트 운영 계층입니다.

문제

메신저 챗봇은 대화는 쉽지만 로컬 파일/개발 도구 실행과 연결하기 어렵고, 대형 에이전트 프레임워크는 운영 부담이 큽니다.

해결

작은 Python 코드베이스로 Discord/Telegram, 기본 LLM, Codex CLI, 파일 업로드, 작업 큐, macOS 서비스, 로컬 dashboard를 묶었습니다.

가치

모바일/데스크톱 Discord에서 Mac mini의 로컬 워크스페이스와 개발 자동화를 호출하고, dashboard에서 처리 이력을 확인할 수 있습니다.

2. 사용자 경험

사용법의미
!nyanya 질문prefix 기반 기본 질의. configured LLM backend로 응답합니다.
@nyanya 질문Discord 멘션 기반 호출. prefix 없이도 동일하게 처리합니다.
!nyanya upload <파일 경로>로컬 워크스페이스 파일을 Discord 채널에 첨부합니다.
!nyanya codex 검수/조사 내용Codex CLI 읽기 전용 위임을 명시합니다.
!nyanya codex-work 파일 생성/수정 요청Codex CLI 쓰기 작업을 명시적으로 요청합니다.
!nyanya status/config/resources브릿지 상태, 설정 요약, 시스템 리소스를 확인합니다.
!nyanya 취소사용자의 진행/대기 작업을 취소합니다.
현재 운영 정체성: 내부 표시명은 NyaNya Agent, Discord 봇 사용자명과 서버 닉네임은 nyanya입니다.

3. 아키텍처

Messenger
Discord / Telegram
→
Bridge
trigger, attachment, upload
→
Policy
allowed roots, protected paths
Queue
per-user current + waiting jobs
→
Router
simple LLM vs Codex
→
Backends
Gemini CLI / Ollama / OpenAI-compatible / Codex
Dashboard
SQLite ledger / usage trend

입력을 바로 실행하지 않고 Bridge → Policy → Queue → Routing → Backend 단계를 거치게 만든 것이 핵심입니다. 이 구조 덕분에 메신저 UI는 단순하지만, 내부에서는 권한 경계와 작업 복잡도에 따라 다른 실행 경로를 선택합니다.

4. 소스 구조

src/nyanya_agent/core.py              # CLI, provider 호출, 세션 저장, 시스템 프롬프트 조립
src/nyanya_agent/discord_bridge.py    # Discord 이벤트 수신, prefix/mention 트리거, 파일 업로드
src/nyanya_agent/telegram_bridge.py   # Telegram long polling bridge
src/nyanya_agent/bridge_store.py      # 대화 저장소, per-user task queue, 홈워크스페이스 매핑
src/nyanya_agent/bridge_runtime.py    # Codex 위임, 자동 라우팅, 리소스 조회, 실행 제한
src/nyanya_agent/bridge_policy.py     # 워크스페이스 경계, 보호 경로, 명령어 도움말
src/nyanya_agent/bridge_constants.py  # 명령어/키워드/기본 정책 상수
src/nyanya_agent/dashboard_store.py   # SQLite 요청/이벤트/프로젝트 단계 ledger
src/nyanya_agent/dashboard_api.py     # FastAPI 기반 local dashboard API
src/nyanya_agent/dashboard_static/    # dashboard HTML/CSS/JS
src/nyanya_agent/manager.py           # macOS 서비스 관리, Discord bot-name API
scripts/                              # 실행/설치/점검 shell scripts
config/                               # 기본 JSON 설정과 사용자 워크스페이스 매핑
prompts/                              # 시스템 프롬프트
docs/                                 # 운영/공개 정책/포트폴리오 문서

프로젝트는 의도적으로 작게 유지되어 있습니다. 큰 framework의 추상화를 가져오기보다, 실제 운영에 필요한 표면만 직접 구현했습니다.

5. 실행 흐름

Discord 메시지 처리

1. 이벤트 수신Discord Gateway에서 메시지를 받습니다.
2. 트리거 판별DM, !nyanya, @nyanya, 허용 채널 자동 응답을 확인합니다.
3. 권한 확인채널/사용자 허용 목록과 파일 공유 채널 정책을 적용합니다.
4. 첨부 처리첨부파일은 허용된 워크스페이스 하위에 저장하고 경로를 컨텍스트로 제공합니다.
5. Ledger 기록요청, trigger, mode, provider/model을 SQLite dashboard DB에 기록합니다.
6. 큐 등록사용자별 작업 큐에 넣고 백그라운드 thread에서 실행합니다.
7. 결과 추적완료/실패, 시작/종료/소요시간, 결과 요약을 dashboard DB에 남깁니다.
8. 응답/업로드결과를 Discord 제한 길이에 맞춰 나누거나 파일로 업로드합니다.

라우팅

단순 질의는 configured LLM backend로 보내고, 파일/코딩/HTML/데이터/Chrome 관련 복잡 요청은 Codex CLI로 위임합니다. 이 판단은 키워드, 파일 경로, 작업 동사, 요청 길이, 브라우저 관련 신호를 조합해 수행합니다.

6. 보안 설계

NyaNya Agent는 완전한 sandbox가 아니라 로컬 에이전트 앞단의 정책 계층입니다. 따라서 공개 운영보다 개인/소규모 팀의 통제된 워크스페이스 운영에 맞게 설계되어 있습니다.
보호 영역설계
워크스페이스 경계NYANYA_WORKSPACE_ROOTS 하위만 파일/코드 작업 범위로 허용합니다.
사용자별 홈Discord/Telegram 사용자별 홈워크스페이스를 지정해 Codex 작업 디렉토리를 분리할 수 있습니다.
보호 삭제 경로.env, src, config, prompts, scripts, 패키지 메타파일 등을 보호합니다.
비밀값토큰/API key는 로컬 .env에 두고, 문서/Discord 응답에는 출력하지 않습니다.
작업 큐사용자별 현재 작업 1개와 제한된 대기열을 사용해 폭주를 줄입니다.
취소사용자 취소와 관리자 전체 취소를 지원하고, 외부 subprocess에도 cancel event를 전달합니다.
대시보드 데이터요청 ledger는 로컬 SQLite에 저장하고 data/, logs/, sessions/는 git에서 제외합니다.

8. 포트폴리오 포인트

작은 코드베이스

대형 프레임워크 복붙이 아니라 운영에 필요한 기능만 선별해 직접 구현했습니다.

메신저-로컬 연결

Discord가 Mac mini 로컬 개발 환경을 호출하는 실질적 운영 UI가 됩니다.

정책 기반 라우팅

단순 질의와 복잡한 파일/코드 작업을 구분해 적합한 backend로 보냅니다.

안전 경계

허용 루트, 보호 삭제 경로, sandbox 모드, 사용자별 홈워크스페이스를 적용합니다.

운영 자동화

LaunchAgent, check/status/restart, bot-name 변경 명령까지 운영 루프를 갖췄습니다.

운영 관측성

Discord 요청의 처리 상태와 일/주/月 사용량 추이를 local dashboard에서 확인합니다.

배포 고려

Python package와 npm wrapper를 함께 제공해 설치 진입점을 낮췄습니다.

9. 향후 개선 방향

  • dashboard 인증/권한과 reverse proxy hardening
  • 명령어/권한 정책을 YAML 또는 TOML로 분리
  • 작업 결과 artifact 인덱싱과 검색
  • Discord slash command 지원
  • 라우팅 정책, Discord 이벤트 핸들러, dashboard API contract 테스트 확대
  • uv tool, Homebrew tap, standalone app 패키징 검토
이 문서는 포트폴리오 공유용으로 생성되었습니다. 운영 비밀값, 개인 식별자, 실제 Discord 채널/사용자 ID는 포함하지 않습니다.
